大家好，我是扑克熊 🐻。

在上一篇中，我介绍了试卷图片如何经过 OCR、判分和错因诊断变成一份错题报告。但发现薄弱点只是开始，系统还要把“二次函数掌握不牢”转换成一组真正可以练习的题目。

最直接的做法是从题库筛选。如果题库数量足够，这条路稳定、快速，也容易追踪题目来源；问题是，当用户同时指定知识点、题型和难度后，小型题库很容易没有足够候选。另一种做法是全部交给大模型生成，但只给一个知识点名称，模型可能生成超出教材范围、题型不一致、依赖缺失配图，甚至答案错误的题目。

我最终采用的是一条混合链路：**先从题目库选题，不足时再让 AI 补题；AI 生成时分别参考教材知识库和可信题目样例，生成后还要经过多层质量门禁。** 本文会从自主组卷和错题巩固两个场景出发，拆解这条链路的实际实现和边界。

## 1. 两个入口，最终进入同一个出题引擎

用户会从两个不同页面接触到出题能力。

### 1.1 自主组卷

在自主组卷页面，用户主动选择年级、学期、教材版本，并按分区配置题型、题数、难度、知识点和每题分值。例如，可以要求系统生成 3 道二次函数填空题和 2 道解答题。

后端收到配置后，不会立刻要求模型生成整张试卷，而是逐个分区处理：

```text
校验知识点范围
→ 按题型、难度和知识点查询题目库
→ 从候选题中随机取题并跨分区去重
→ 计算缺口
→ 只对缺少的数量调用 AI
→ 合并题目并保存试卷草稿
```

这里的核心原则是“题库优先”。如果某个分区需要 5 道题，SQL 已经找到 5 道符合条件的题，AI 不会参与；如果只找到 3 道，系统才生成剩余 2 道。

### 1.2 错题巩固

巩固练习的入口不同。错题分析报告会先给出薄弱知识点和分阶段练习建议，用户确认后，系统把每个阶段的题量、题型、难度范围和知识点转换成组卷分区。

转换完成后，巩固服务直接调用同一个 `generate_paper()` 出题引擎：

```text
错题报告中的巩固计划
→ 转换为组卷分区
→ 题目库检索 + AI 补足
→ 建立巩固任务与题目关联
→ 用户逐题作答并查看结果
```

因此，自主组卷和巩固练习不是两套独立的出题实现。前者的条件来自用户手动配置，后者的条件来自错题报告，但两者共用题库检索、AI 生成、质量检查和试卷组装能力。这样可以避免同一种题目在两个入口中执行不同的质量标准。

由于 AI 补题可能经历生成、校验和重试，两个入口都采用后台生成：接口先返回任务 ID，前端再轮询进度；自主组卷完成后读取试卷详情，巩固练习完成后进入作答页面。当前任务状态主要依赖单进程内存和 FastAPI 后台任务，还不是基于 Redis、Celery 等组件的生产级任务系统。

## 2. 知识点目录、教材知识库和题目库不是一回事

这条链路里有三类容易混淆的数据。

### 2.1 知识点目录负责统一坐标

当前数据库中的知识点目录包含 29 个章节点、98 个节节点和 354 个具体知识点节点，覆盖七、八、九年级上下学期。它的作用不是直接给模型提供讲解或题目，而是提供一套稳定的分类坐标。

教材内容块和题目都关联到这套目录。系统收到知识点 ID 后，还会检查它是否属于当前学科、年级、学期和教材版本，避免把不同范围的内容混入同一张试卷。

需要说明的是，完整目录不等于教材正文已经覆盖全部 29 章。当前数据库中有 571 条九年级教材内容块，教材正文覆盖范围仍小于知识点目录。文章里把这两个数字分开，是为了避免把“已经建立分类目录”误写成“所有年级教材均已完整入库”。

### 2.2 教材知识库提供知识依据

教材知识库存放在 `textbook_chunks` 表中，每个内容块可能是定义、性质、公式、探究过程、例题讲解或练习片段。运行时有两条检索路径：

- 精确检索先按知识点及其所在教材范围查询内容块，优先保证命中目标范围。
- 语义检索使用 `textbook_index.faiss` 找到表达不同但含义相关的教材片段。

两路结果会去重、合并，并在字符预算内安全截断。语义索引或向量模型不可用时，系统保留精确检索结果，而不是让整个出题流程失败。

这些内容的职责是告诉模型“教材怎样定义这个概念、通常使用什么方法、有哪些范围限制”。它不是最终用于组卷的题目池。

### 2.3 题目库提供可信例题和可复用题目

题目库存放在 `questions` 表中，通过 `question_kp_map` 与知识点目录关联。当前有效题目主要来自 PDF 导入，AI 生成题则使用 `ai_gen` 标记并默认保持为 `draft`。

题目库承担两个不同角色：

1. 组卷时，SQL 按年级、学期、教材版本、知识点、题型和难度筛选可以直接使用的题目。
2. AI 补题时，只从 `pdf_import` 或人工录入且状态为 `active` 的题目中，按知识点精确匹配、难度就近选择少量 few-shot 样例。

所以，教材知识库和题目库并不是同一个库。前者提供知识依据，后者提供可信例题和现成题目；两者只是通过统一的知识点 ID 对齐。

## 3. AI 补题前，先准备两类上下文

当题目库出现缺口时，`generate_questions()` 会为这一批题准备两类 RAG 上下文。

第一类是教材讲解。系统对目标知识点执行精确检索和 FAISS 语义检索，默认把合并后的内容控制在有限字符数内。教材上下文会同时用于首次生成和后续校验，不会在每次重试时重新检索一套可能不同的内容。

第二类是可信题目样例。SQL 会按照知识点、题型、年级和难度筛选少量样例，排除 AI 生成题、非正式状态题目以及依赖缺失配图的题目。样例中保留题干、答案和解析，帮助模型对齐题目形式、考查粒度和难度。

随后，Prompt 同时告诉模型：

- 要生成哪个年级、知识点、题型和难度的题；
- 教材对这个知识点给出了什么定义和方法；
- 可信题目通常怎样组织条件和答案；
- 返回结果必须满足怎样的 JSON 结构。

教材和例题在这里承担不同职责。只给教材，模型知道“应该讲什么”，但未必知道“题目应该长什么样”；只给例题，模型可能模仿题型，却缺少明确的知识边界。两类上下文结合，才形成“知识依据 + 题目范式”。

## 4. 生成成功不等于题目可以使用

模型返回内容后，系统不会直接写入题库。当前链路包含几层不同性质的检查。

### 4.1 解析与结构检查

服务先尝试把模型响应解析为 JSON。即使模型把 JSON 包在 Markdown 代码块里，也会进行兼容提取；连续生成失败时最多进行有限次数的重试。

解析成功后，确定性校验会检查字段、题型和内容之间是否一致。例如，填空题不应该带选择题选项或使用选项字母作为答案；单选题需要合法选项；题干如果写着“如图”却没有配图，也不能继续进入组卷。

### 4.2 模型自校验与补生成

结构通过后，另一轮 Prompt 会逐题检查答案正确性、知识点相关性、难度、题型规范和教材一致性。不合格题会被剔除，系统只对缺少的数量进行有限轮次补生成，而不是推翻整批合格题重新开始。

模型自检可以发现语义问题，但它仍然可能重复生成模型自己的错误，因此不能作为唯一证据。

### 4.3 多证据验证

通过自检的题还会进入多证据验证管线。当前管线组合了：

- 确定性规则，检查选项、缺图、答案格式等硬约束；
- SymPy，在安全支持的方程、表达式和部分选择题范围内进行符号计算；
- 独立模型，在不读取候选答案和解析的情况下重新求解；
- 本地审核题库，对题干完全匹配的可信题比较答案；
- 确定性仲裁器，根据证据强度得出 `verified`、`review_required` 或 `rejected`。

强证据明确否定答案时，题目会被拒绝。只有 SymPy 或本地可信题库这类强证据才能触发安全纠正；纠正后还必须重新跑完整验证，并检查新解析是否与纠正后的答案一致。证据不足时，系统不会把题目包装成“已自动验证”，而是保留人工复核语义。

## 5. 为什么 AI 题默认不进入正式题库

通过生成链路的 AI 题会以 `source="ai_gen"`、`status="draft"` 写入数据库，并记录知识点关联和验证运行轨迹。它可以被当前试卷引用，但不会因为一次模型生成就自动变成 `active` 的正式题库题目。

这一区分解决了两个问题。

第一，当前组卷任务需要继续完成，不能因为正式审核尚未发生就丢掉已经通过门禁的补充题。第二，长期题库需要更高的复用门槛；如果未经人工审核的 AI 题自动变为正式题，下一次它又可能被当作可信样例，形成“AI 题生成 AI 题”的质量反馈循环。

因此，当前策略是：

```text
明确不合格 → 拒绝且不写入
通过生成门禁但尚未正式审核 → draft
可信导入或人工维护 → active
```

这里的“draft”不是失败，而是对证据边界的诚实表达。

## 6. 如何验证这条出题链路 ✅

我把测试重点放在“不同数据源有没有越界”和“不合格题会不会漏过门禁”，而不只是接口是否返回成功。

教材检索测试覆盖精确结果优先、FAISS 结果去重、跨章节内容限制、公式安全截断，以及语义检索失败后保留精确路径。题目样例测试检查只返回可信且有效的来源、知识点必须匹配、难度按距离排序，并明确排除 `ai_gen` 和 `draft`。

生成侧测试覆盖错误 JSON 的兼容解析、题型结构冲突、缺图依赖、自校验拒绝后不写库，以及多证据拒绝后只补足缺口。学期隔离测试还会验证跨学期知识点不能进入试卷，换题也必须停留在原试卷范围内。

不过，这些测试主要证明代码约束按预期执行，并不等于所有 AI 数学题都已经正确。复杂几何、证明题和依赖图形的题目仍然很难被 SymPy 等确定性工具覆盖；独立模型也不是绝对正确的裁判。因此，系统选择对证据不足的题保留 `draft` 和人工复核，而不是给出无法支撑的全自动正确率承诺。

## 7. 项目目前的不足 🌱

这条链路已经能够支撑面试演示版的自主组卷和错题巩固，但离生产系统还有几个明显距离：

1. **教材正文覆盖不完整**：知识点目录覆盖六个学期，但当前教材块主要集中在九年级内容，其他范围可能只能退化到题目样例或无教材上下文生成。
2. **题目库规模有限**：筛选条件越具体，越容易触发 AI 补题；题库还需要持续扩充和人工审核。
3. **验证器覆盖有限**：SymPy 只能处理安全支持的部分代数题，复杂几何和证明题仍依赖模型与人工复核。
4. **后台任务是单机实现**：缺少持久化队列、重试调度、跨进程状态和任务监控。
5. **正式题库审核闭环仍需完善**：AI 草稿已有验证轨迹，但还需要更完整的人工审核页面和发布流程。

这些边界也解释了为什么我没有把方案概括成“RAG 可以解决题目正确性”。RAG 改善的是上下文和生成条件，正确性仍然要由结构约束、独立证据、状态分层和人工复核共同保证。

## 8. 写在最后 ✨

实现这条链路后，我对“AI 出题”的理解发生了变化。真正困难的部分不是调用一次模型，而是回答四个工程问题：什么时候应该使用已有题目，模型生成前应该看到什么，生成后由谁验证，以及证据不足时题目应该进入什么状态。

错题星把知识点目录作为统一坐标，把教材知识库作为知识依据，把题目库作为可信例题和现成题目来源；组卷时先查题库，只让 AI 补缺口；生成结果经过结构、自检和多证据验证后，仍然以草稿状态隔离。自主组卷和巩固练习共用这套引擎，只在上游配置来源和下游使用方式上有所不同。

下一篇我会继续介绍 LangGraph 智能助教：它如何在错题、教材、题目库和练习能力之上，根据用户问题动态选择工具，同时把真正产生数据的操作停在用户确认阶段。
