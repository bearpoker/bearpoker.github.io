# 博客文章写作规范

本文件是本博客文章的唯一写作与格式规范。创建、续写或修改
`src/content/blog/` 中的文章前，必须完整阅读本文件。

## 一、写作目标

文章需要同时服务三个目标：

1. 帮助作者重新梳理并真正理解项目。
2. 向面试官展示作者的真实工作、技术判断和验证方法。
3. 为读者提供能够迁移到其他项目的经验。

项目文章不能写成简历条目的扩写，也不能只罗列技术栈。优先使用以下叙述顺序：

> 问题是什么 → 为什么难 → 考虑了什么 → 为什么这样设计 → 如何实现 → 如何验证 → 还存在哪些边界

## 二、事实核查规则

写项目文章前，必须先阅读对应项目的当前代码、README、架构或验收文档。

- 以实际代码和最新验收材料为准，旧规划文档只能作为背景，不能当成已实现事实。
- 不得根据简历中的技术关键词自行推测业务链路。
- 不得虚构指标、技术选型理由、测试结果或用户效果。
- 规划中尚未实现的内容必须明确写成“计划”或“后续方向”。
- 如果资料互相冲突，应先核对代码；仍无法确认时，在文章中保守表述或询问作者。

## 三、文件与 Frontmatter

文件使用小写英文和连字符命名，例如：

```text
src/content/blog/llm-rag-mistake-system-retrospective.md
```

每篇文章必须包含以下 Frontmatter：

```yaml
---
title: '清晰、具体的中文标题'
description: '用一句话说明文章解决什么问题，避免只重复标题。'
pubDate: YYYY-MM-DD
---
```

可选字段：

```yaml
updatedDate: YYYY-MM-DD
heroImage: '../../assets/example.jpg'
```

字段必须符合 `src/content.config.ts`。不要自行添加未定义字段。

## 四、默认文章结构

项目复盘文章默认使用以下骨架，可根据内容删减，不要为了凑结构机械填充：

```markdown
---
title: '文章标题'
description: '文章摘要'
pubDate: YYYY-MM-DD
---

大家好，我是扑克熊 🐻。

用两到三段介绍项目、真实问题和本文范围。

## 为什么做这个项目 💭

说明真实需求和目标。

## 系统全貌 🗺️

先给整体流程，再进入局部细节。

## 核心链路或关键设计

解释输入、处理过程、输出和设计取舍。

## 最难的问题与解决方式 🕳️

说明失败、权衡和边界，不回避问题。

## 如何验证 ✅

交代测试集、指标、失败样本与评价标准。

## 项目目前的不足 🌱

区分已实现能力和后续计划。

## 写在最后 ✨

总结可迁移的经验，并预告后续文章。
```

## 五、Markdown 层级

- 文章标题来自 Frontmatter，正文中不要再写 `#` 一级标题。
- `##` 用于文章主要章节。
- `###` 用于章节内的子主题。
- `####` 只在确实需要第四层结构时使用。
- 不要用加粗文本冒充标题，例如不要写 `**## 标题**`。
- 列表使用标准 Markdown，不要在 `-` 和 `*` 前添加转义符。
- 流程可以使用短代码块表达，但不要用代码块代替大段正文。

正确示例：

```markdown
## Agent 如何控制写操作

先解释问题和设计目标。

### 人工确认

再解释具体实现。
```

## 六、统一视觉规格

文章字体、字号、行高、标题间距和移动端适配统一由
`src/layouts/BlogPost.astro` 控制。

- 不在 Markdown 中写 HTML 字号、居中或颜色样式。
- 不为某一篇文章单独覆盖标题字号。
- 需要调整全站文章排版时，只修改公共布局，不批量修改文章正文。

当前规格：

| 内容 | 桌面端规格 |
|---|---:|
| 文章标题 | 2.1rem |
| 日期 | 0.95rem |
| 二级标题 | 1.55rem |
| 三级标题 | 1.25rem |
| 四级标题 | 1.1rem |
| 正文 | 1rem，行高 1.8 |
| 代码块 | 0.9rem，行高 1.6 |

## 七、语言风格

- 使用自然、克制的第一人称，不写成产品宣传稿。
- 技术名词出现时说明它在项目中解决了什么问题。
- 明确区分“我实现了什么”“框架负责什么”“模型决定什么”。
- 使用真实数据时解释指标口径，必要时呈现失败案例。
- 可以使用少量 emoji 延续博客风格，每个主要章节最多一个。
- 避免“非常强大”“轻松实现”“完美解决”等缺少证据的表达。

## 八、完成检查

提交文章前逐项检查：

- [ ] 已核对来源项目的当前实现，而不是只看简历或旧方案。
- [ ] Frontmatter 字段完整，日期为 `YYYY-MM-DD`。
- [ ] 正文没有重复的一级标题。
- [ ] 标题层级连续，没有用粗体冒充标题。
- [ ] 已实现、测试结果和未来计划表达清楚。
- [ ] 没有虚构数据或夸大项目能力。
- [ ] 没有添加单篇文章专用的排版样式。
- [ ] 已运行 `npm.cmd run build` 并确保构建通过。
