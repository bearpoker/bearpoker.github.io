# 错题星博客系列写作规划

## 写作目标

错题星系列文章同时服务三个目标：

1. 帮助自己重新梳理项目，理解各模块之间的依赖和设计取舍。
2. 向面试官展示完整的 AI 应用工程能力，而不是只展示模型调用。
3. 为其他开发者提供可复用的 OCR、RAG、Agent 和可靠性实践经验。

## 推荐篇数

推荐使用 **5 篇文章**介绍错题星。

用户操作不单独拆成第 6 篇，而是在第 1 篇中集中讲清楚；第 2 至第 5 篇再分别从一次真实的页面操作切入内部实现。这样既能覆盖项目重点，也不会拆得太碎。

## 第 1 篇：项目全貌与用户使用流程

### 建议标题

《从错题分析到巩固练习：我的「错题星」项目复盘》

### 主要内容

- 项目最初为什么从错题识别开始。
- 为什么后来需要教材、题库、组卷、巩固练习和 Agent。
- 错题分析、自主组卷、巩固练习三条业务链路。
- Agent 是建立在已有业务能力之上的智能交互入口。
- 系统整体架构、模块关系、当前限制和改进方向。
- 用户打开页面后如何实际操作。

### 用户操作路径

```text
错题分析：
登录 → 上传试卷 → 核对识别结果 → 开始分析
→ 查看报告 → 生成巩固练习 → 作答并查看结果

自主组卷：
选择年级和学期 → 配置题型、数量、难度、知识点和分值
→ 生成试卷 → 换题或查看答案 → 确认试卷

智能助教：
新建会话 → 可选关联历史错题报告 → 输入问题
→ Agent 查询错题、教材或题库
→ 确认生成题目或创建练习 → 查看结果
```

### 文章作用

让普通读者和面试官快速理解“错题星是什么、能做什么、怎么使用”，同时帮助自己建立项目全局认识。

## 第 2 篇：OCR 与错题分析管线

### 建议标题

《三类图片如何变成错题报告：错题星 OCR 与分析管线》

### 主要内容

- 试卷图片、学生答题卡、标准答案分别解决什么问题。
- 为什么试卷必须上传，另外两类图片可以不上传。
- OCR 如何提取题目、选项、学生答案和参考答案。
- Pydantic 如何约束中间数据。
- 为什么用户需要核对 AI 补全的标准答案。
- 判分、错因诊断、知识点定位和报告生成。
- OCR 错误如何向后传播。
- 为什么确定性分析流程没有使用 LangGraph。

### 推荐叙事路径

```text
点击“上传并识别” → 上传文件 → OCR → 结构化题目
→ 用户核对 → 判分 → 知识点定位 → 生成报告
```

## 第 3 篇：教材 RAG、题库与出题引擎

### 建议标题

《题库不够怎么办：教材 RAG 与 AI 补题实战》

### 主要内容

- 29 章、98 节、354 个知识点的教材结构。
- 数据库知识点目录、FAISS 教材检索和 SQL 题库检索的职责区别。
- 为什么教材用于提供知识依据，题库用于提供可信例题。
- 题库优先、AI 补足的组卷策略。
- AI 如何结合教材解释和可信原始例题生成题目。
- 结构校验、重试和多证据验证。
- 不合格题目为什么不进入正式题库。
- 自主组卷和巩固练习如何共用出题引擎。
- 异步生成和进度查询。

### 需要覆盖的两个场景

1. 用户主动配置条件进行自主组卷。
2. 系统根据错题报告中的薄弱知识点生成巩固练习。

## 第 4 篇：LangGraph 智能助教

### 建议标题

《LangGraph 实战：让 Agent 连接错题、教材与练习》

### 主要内容

- 为什么智能助教不是普通聊天机器人。
- 6 个只读工具与 2 个写操作提案工具。
- LLM、LangGraph、工具函数和业务服务的职责边界。
- Agent 如何动态决定调用哪些工具。
- 不关联报告时如何按年级或知识点复习。
- 关联报告后如何查询具体错题并生成针对性练习。
- 最近 12 条消息如何恢复多轮上下文。
- 为什么采用单 Agent，而不是多 Agent。
- 为什么没有把 OCR、判分和组卷全部改造成 Agent。

### 推荐演示问题

1. “帮我查一下二次函数的教材内容并推荐练习。”
2. “根据上次错题报告，帮我生成一组巩固练习。”

## 第 5 篇：Agent 可靠性与评测

### 建议标题

《如何让 Agent 可控：人工确认、Checkpoint 与评测》

### 主要内容

- 为什么查询工具可以直接调用。
- 为什么生成题目和创建练习需要人工确认。
- Pending Action 如何保存待执行操作。
- 用户确认后如何从 Checkpoint 恢复。
- 参数冻结和哈希校验。
- 所有权、状态和有效期校验。
- 幂等执行与重复确认处理。
- 工具调用预算、循环检测、超时和模型降级。
- 用户数据隔离。
- 固定评测集如何设计。
- 真实模型用例和确定性场景如何配合。
- 失败案例如何帮助发现系统问题。

### 当前评测数据

- 26 条固定任务。
- 42 次真实工具调用。
- 18 条真实模型用例。
- 8 条确定性场景。
- 当前结果为 26/26。
- 历史 23/24 结果只用于说明系统演进，不应写成当前最终结果。

## 推荐写作顺序

```text
第 1 篇：项目总览和用户操作
  ↓
第 2 篇：OCR 与错题分析
  ↓
第 3 篇：RAG、题库与出题
  ↓
第 4 篇：LangGraph Agent
  ↓
第 5 篇：可控性与评测
```

按这个顺序写，可以先理解底层业务能力，再理解 Agent 如何组织这些能力，最后分析系统如何保证可靠性。

## 五篇文章分别回答的问题

| 文章 | 核心问题 |
| --- | --- |
| 第 1 篇 | 错题星是什么，用户怎么使用？ |
| 第 2 篇 | 图片怎样变成错题报告？ |
| 第 3 篇 | 系统怎样可靠地生成题目？ |
| 第 4 篇 | Agent 怎样组织已有业务能力？ |
| 第 5 篇 | 怎样保证 Agent 安全、稳定、可评测？ |

## 写作时的统一要求

- 以当前代码和当前数据为准，不直接照搬简历中的旧数字。
- 每篇先从用户看到的操作或问题切入，再解释内部实现。
- 不只介绍“做了什么”，还要说明“为什么这样设计”和“没有采用什么方案”。
- 区分已经实现的能力、实验结果和未来计划。
- 涉及代码事实或评测数字时，在发布前重新检查错题星项目。
- 文章格式遵循 `docs/blog-writing-guide.md`。
